# Standalone AGC Camera 1.8.6: import the ZIP

**Download [Basile-AGC-Camera-profile.zip](../generated/Basile-AGC-Camera-profile.zip). Keep it zipped.** In the standalone app (`com.agc.gcam`), open **Ajustes → Perfis → ⋮**, use the profile import action, and select that file. Then select **Basile** in the profile list. Do not use the GitHub source-code ZIP, the GCam mod's `.agc`, or the optional Lightroom `.xmp` in this screen. A device report confirmed the Profiles panel rejects the XMP as an unsupported file type.

**Back up first.** Export and retain your current native profile ZIP, including its LUT files. Applying a v4 profile is a **replacement**, not a patch: the app clears existing profile-managed color/noise/AWB/CCT/LUT and tunable/lens overrides and applies the new profile. Importing a ZIP into the list and selecting it for use are separate steps. To revert, reimport your saved ZIP and select your previous profile. Do not delete the old profile or its external assets while testing.

## What Basile applies

- **Photo, Portrait, Night:** the same six native adjustment offsets for saturation, contrast, exposure compensation, shadows, denoising and sharpening. Each is set to the app's own neutral numeric baseline (0), **not** a GCam patch value translated across engines. Zero is an adjustment offset; it does not switch off the processing pipeline.
- **Still HDR:** preserves the actual exported still-photo HDR preference (`pref_hdr_mode_key: 1`). On this build value 1 selects HDR+ On (not Enhanced), where supported. This is not a request for 10-bit HDR video and is not evidence of an embedded Ultra HDR gain map.
- **Lenses and color:** no creative LUT, per-lens override, fixed white balance or invented noise calibration. The supplied example used a creative LUT on one lens. Deliberately not reproducing it gives the lenses a consistent starting point; equal perceptual results are not yet measured. The LUT itself is neither required nor redistributed.
- **Not set by this profile:** video HDR, video frame rate, codec, stabilization, RAW format, or launcher icon. Use the app's own controls where available. For the old GCam icon, choose it in the standalone app's desktop/icon setting. BigKaka [added this choice in 1.8.0](https://www.celsoazevedo.com/files/android/agc-camera/f/dl06/) and [fixed an icon-switching crash in 1.8.5](https://www.celsoazevedo.com/files/android/agc-camera/f/dl07/).

## Format and evidence

A native export from the app establishes a v4 profile as a flat root JSON member with `format: "GCamAGC-profile"`, `_version: 4`, a display name, and `photo`, `portrait`, `night` sections with `global`, `per_lens`, and `tunable_settings`. A profile with external LUTs can include a `luts/` directory. Our independently authored ZIP contains just **Basile.json**, with no timestamp from the source export or third-party assets. Generated bytes are deterministic across time zones.

The [1.7.0 changelog](https://www.celsoazevedo.com/files/android/agc-camera/f/dl05/) documents the native profile bundle. We checked the envelope against an actual private export and inspected the serialization/application behavior of the [officially distributed 1.8.6 build](https://www.celsoazevedo.com/files/android/agc-camera/f/dl08/1/) to distinguish an accepted setting from a guessed one. Neither the original export, the app binary, nor implementation code from the app is published. The generated ZIP is structurally validated; **its successful round trip and photographic behavior still require a device test**.

The [Adobe Camera Raw XMP](../generated/Basile-AGC-Camera-photo-look.xmp) is a separate neutral photographic color preset, retained for existing workflows. The [developer listing](https://play.google.com/store/apps/details?id=com.agc.gcam) advertises Lightroom XMP import, but that is not what the Profiles screen accepts. Do not rename an XMP to ZIP. Do not interpret this optional XMP as native capture settings.

## Acceptance on the S23

1. Confirm the build; use the native ZIP import action; verify **Basile** appears and can be selected.
2. Cold-start the app, re-export Basile and inspect the JSON in the new ZIP. Compare effective values rather than timestamps, default omissions, member order, or whitespace.
3. Compare a backed-up default profile to Basile in all three modes, on lenses available in that mode, using the same daylight/indoor/low-light scenes. Inspect skin, neutral balance, bloom, shadows and fine texture. Keep original files private.
4. Validate HDR still gain-map payloads and HDR video/cadence separately. No output format can by itself establish better stabilization, eliminate stutter, or certify comparable rendering between the Samsung and AGC pipelines.
